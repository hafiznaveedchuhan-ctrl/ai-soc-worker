`evals/reports/<date>-paid-report.md`. The paid run itself (R5) is NOT part of this feature.

======================================================================
2. SPEC (what it must do)
======================================================================
FR-11-01  `python -m soc_evals paid` runs only with BOTH `--yes-paid` AND env CONFIRM=haan.
          Otherwise it prints "refused ..." and makes zero calls (exit 1).
FR-11-02  Alerts: each alert goes through agent_service.flows.run_triage with its
          analyst context from context.csv. Ticket approvals are always REJECTED (no tickets,
          even mock ones). One fresh session per alert.
FR-11-03  Probes: each probe goes through run_ask with a fresh session per probe (no memory
          shared between probes).
FR-11-04  Mapping FlowResult → prediction (existing AlertPrediction / ProbePrediction models):
            ok        → note/answer, output_text = r.text (MASKED text, so the leak check is real)
            declined  → scope_label = DECLINE, output_text = the decline text
            blocked / max_turns / budget / error → error = "<status>: <text>",
                         probes keep scope_label from the fallback answer
          usage = r.usage (tokens + cost per call), latency_ms measured around each flow call.
          An unexpected exception on one item → error on that item; the run continues.
FR-11-05  Money guards: (a) per-item budget = existing run budget $0.05; (b) a RUN-WIDE cap
          `--max-usd` (default 1.50): when the running total reaches it the run STOPS, writes
          what it has, and the report says "stopped at cap"; (c) the existing $9 ledger is
          checked before every item.
FR-11-06  Pilot options: `--only alerts|probes`, `--ids EV-A003,EV-P001,...`, `--limit N`.
          A partial run is scored only on the items it ran (report says "partial: k/n items").
FR-11-07  `python -m soc_evals estimate` (FREE, offline): prints the expected and pessimistic
          cost of a full run from the dataset sizes + prompt sizes + the gpt-5-nano price.
FR-11-08  Pre-flight (free): the handbook MCP must answer `list_tools` (no search, no embedding),
          else stop with "start the handbook: cd ../handbook && npm run serve".
FR-11-09  Outputs: `evals/recordings/paid/<date>-<sha>-{alerts,probes}.jsonl` (masked only) +
          `evals/reports/<date>-paid-report.md` with total cost, tokens, p50/p95 latency.
FR-11-10  Privacy: trace export OFF by default (same as the demos); `--export-traces` opts in
          (traces are masked + trace_include_sensitive_data=False anyway).
FR-11-11  Dependencies in the live run:
            KSOR       = LIVE handbook (the fake KSOR does not hold all expected pages)
            Wazuh      = fixtures (evals/data/alerts — the same 40 files)
            AbuseIPDB  = real only if ABUSEIPDB_API_KEY is set, else "not configured"
                         (NOT the test mock: its fixed score 88 would bias verdicts)
            Web search = Tavily only if WEB_SEARCH_API_KEY is set, else "web search unavailable"

Out of scope: running the paid eval (R5), concurrency (items run one by one), model upgrades.
