2. FINDINGS
======================================================================
F1  ACCOUNTING BUG (Claude's).
    When a flow raises an exception (here ModelBehaviorError), the usage already spent is lost from the
    prediction. Effects:
    - the report undercounts the spend;
    - the run-wide cap counts less than the real spend.
    The $9 ledger IS correct, because the hooks write it per call.
F2  EV-A034 invalid output.
    The SDK error is "Invalid JSON when parsing model output". It is a pydantic ValidationError on
    TriageNote, and the SDK redacts the detail. The JSON matched the schema but broke one of OUR
    cross-field rules (model_validator: e.g. escalate ↔ escalate_condition, or severity rules).
    A strict JSON schema cannot express those rules, so the model cannot see them. Effects:
    - the run dies instead of getting a chance to correct itself;
    - flows.py does not catch this, so /triage in the API would return a 500 as well.
F3  The research answer without web search is a handoff sentence, not an answer.
    The Tavily key is missing, so cyber_research_agent got "web search unavailable" (55 output
    tokens). The final text was the router's "Transferring to…". The scorer counts it as a "valid
    answer" (not_in_record=True), but an analyst learns nothing from it.
F4  EV-A003: verdict needs_info, the label says TP.
    This is a model-quality question; the label is still unreviewed. Not a code bug. Judge it only
    after the full run and the label review (constitution VI.2: upgrade one agent only with an ADR).
F5  Latency: about 90–145 s per alert (gpt-5-nano reasoning tokens ≈ 1.6x input).
    A full run, done sequentially, takes about 1.5–2 hours.
