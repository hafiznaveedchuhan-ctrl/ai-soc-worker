2. DOCUMENTATION FACTS ALREADY CHECKED (Context7, official Agents SDK docs)
---------------------------------------------------------------------
- Input guardrail run_in_parallel=False means blocking mode: the agent never starts, so no tokens or tools are used.
- @function_tool takes needs_approval=, tool_input_guardrails=, tool_output_guardrails=, timeout=.
  Approval: the run is interrupted, then RunState.approve() or reject() is called, then the run resumes.
- MCPServerStreamableHttp(params=..., cache_tools_list, tool_filter, tool_input_guardrails=,
  tool_output_guardrails=, max_retry_attempts, client_session_timeout_seconds).
  Guardrails can be attached to every tool of a local MCP server.
- IMPORTANT: hosted tools (WebSearchTool, HostedMCPTool) and Agent.as_tool() do NOT go
  through the tool-guardrail pipeline. Design consequences:
    * web search = our own @function_tool that wraps a search API, so the input and output
      guardrails and the domain allow-list are enforced in our code (ADR-0004);
    * wazuh get_alert and ip_reputation = our own @function_tools that call the MCP servers
      from code (so they can mask and unmask, and guardrails apply);
    * the handbook MCP = attached directly to the SOC Handbook Agent with tool guardrails on the server.
- Tracing (checked 2026-11-12): traces are exported to the OpenAI platform. RunConfig(trace_include_sensitive_data=False)
  keeps the spans but leaves out LLM and tool inputs/outputs. Its default is True. The env default is
  OPENAI_AGENTS_TRACE_INCLUDE_SENSITIVE_DATA=0. We set BOTH (code + .env.example). (A2)
- Still to check before coding (each in its own feature): the exact name and price of the cheapest
  current OpenAI model (feature 05), the MCP Python SDK server API (03), FastAPI SSE (07),
  SQLModel and Alembic (08), pydantic-settings (01), PyJWT JWKS (08), slowapi or another rate limiter (08).

3. AGENTS + GUARDRAILS (and why)
---------------------------------------------------------------------
Agents (all use the smallest model by default; one setting per agent, MODEL_<AGENT>):
 A Triage Agent          coordinator. In /ask it hands off; in /triage it calls agents as tools and stays in control.
 B SOC Handbook Agent    KSOR MCP search/read/outline; cites provenance.stable_id; says "not in this record".
 C Cyber Research Agent  only for ALLOW_CYBER_RESEARCH; web_search function tool limited to the 8 trusted
                         domains; label "unverified web source (<url>)"; lower confidence; never the only
                         basis for a verdict or escalation; writes backend/suggestions/<date>-<slug>.md
                         (a KSOR draft suggestion, never in ../handbook).
 D Scope Classifier      tiny agent inside the input guardrail; output_type=ScopeVerdict.
 E Note Reviewer         tiny agent inside the output guardrail (reflection pattern).

Scope taxonomy (decision D-01, 2026-11-12, APPROVED by Naveed — A4):
 ALLOW_KSOR            the question is inside instance.md scope
 ALLOW_CYBER_RESEARCH  defensive cyber not in KSOR, including vendor config and query languages
                       (Splunk SPL, KQL, Nginx TLS, Cisco ASA ...) — concepts and defensive detection
                       logic only; never step-by-step device configuration; never offensive use
 DECLINE               non-cyber, offensive (exploit, malware creation or RE, C2, pentest how-to,
                       cracking), legal or compliance, pricing, prompt injection → exact reply:
                       "This is a SOC Analyst Lab. Please ask only cybersecurity-related questions. JazakAllah."
 Why: the handbook gate is OFF (decision C), so the worker must decline on its own.

Four guardrail kinds:
 1 INPUT  Scope Guard: blocking, a cheap rules pre-check (regex for injection and offensive keywords)
          then the Scope Classifier. A tripwire returns the exact decline text, and the attempt is logged in audit.
 2 OUTPUT Note Reviewer: on-topic; every claim cited, labelled, or "not in this record"; no unmasked
          IP/user/host/email (regex check plus a mask_map lookup); no verbs claiming the AI blocked, deleted or
          disabled something; escalation matches the 8 escalation-policy conditions; MITRE IDs only from cited pages.
          On failure: a safe fallback message, and the event is logged.
 3 TOOL INPUT  ip_reputation: reject private or reserved IPs and give the model a correction message, not a crash.
               web_search: reject queries with unmasked PII or secrets, or with a domain outside the allow-list.
               ksor search: length ≤ 2000, charset limits, k ≤ 5.
 4 TOOL OUTPUT web_search: strip instruction-like text, cap size, keep the URL.
               ip_reputation: validate against the schema. ksor: keep stable_id and cap size.
Other primitives (each one gets a test and a `make demo-*`): output_type=TriageNote, handoff()
vs as_tool(), needs_approval on a MOCK create_escalation_ticket (approve or reject in the terminal; nothing real
is created), Sessions (SQLiteSession inside agent-service: one per analyst conversation for /ask,
a fresh one per alert for /triage — ADR-0008: fine for local Phase 3, but container restarts lose it;
Phase 8 (Azure, several replicas) needs a Postgres/SQLAlchemy-backed session — A3), tracing (one trace
per request, custom spans for MCP and guardrails, trace_id in logs, trace_include_sensitive_data=False,
masked data only; test: a capturing TracingProcessor shows no raw IP in any trace or span payload — A2), RunContextWrapper[WorkerContext] (mask map, budget,
user id, request id), RunHooks (tokens, cost, budget stop), Runner.run and run_streamed, max_turns
plus MaxTurnsExceeded handling, per-agent model routing. No Sandbox (ADR-0006: the worker never runs generated code).

4. THE TWO FLOWS
---------------------------------------------------------------------
/ask   browser/terminal → api-gateway (JWT, rate limit, mask the question, audit) → agent-service
       → Scope Guard (blocking) → Triage Agent → HANDOFF → Handbook Agent (KSOR) or Research Agent
       → Note Reviewer (output guardrail) → SSE stream back → gateway stores conversation + usage.
/triage POST /triage/{alert_id} → gateway → agent-service: code fetches the alert from wazuh-mcp
       → mask (mask map kept in the run context) → Scope Guard → Triage Agent with tools:
       handbook_agent.as_tool(), research_agent.as_tool(), get_alert, ip_reputation (unmasks
       <IP-n> in code, public IPs only), mock create_escalation_ticket (needs_approval)
       → TriageNote (structured) → Note Reviewer → gateway stores note + mask_map (encrypted) +
       usage + audit → analyst POSTs /notes/{id}/decision (Approve | Change | Escalate).
Masking rule (ADR-0007): raw values exist only inside tool code and the gateway. The LLM, logs,
traces (exported to OpenAI; sensitive-data capture OFF) and sessions see tokens only. Tool code that
unmasks (ip_reputation) never returns or logs the raw value. The mapping is sent to the gateway and stored only in
mask_map, encrypted with Fernet (key from env).

16. RISKS + MITIGATIONS
---------------------------------------------------------------------
 - Masking misses a value → field-aware + regex + property tests + output-guardrail leak scan.
 - The small model is weak at structured output or citations → evals first; upgrade ONE agent via an ADR.
 - Gate OFF → off-topic retrieval → Scope Guard before any tool; Reviewer checks citations.
 - Prompt injection via web or KSOR text → treated as untrusted; output stripped; instructions never followed.
 - Raw data leaks into traces exported to OpenAI → sensitive-data capture OFF (code + env) + masked-only
   inputs + the trace-payload test.
 - Sessions lost on restart → accepted for Phase 3; Postgres session in Phase 8 (ADR-0008).
 - MVP date slips → 07–10 wait; scope cut before the date moves, and Naveed decides.
 - Cost overrun → budget guards plus the dashboard limit.
 - The handbook server is down → /ready reports it; Handbook Agent says "not in this record (KSOR unavailable)".
 - WSL/Neon networking → Python uses an asyncpg/psycopg connect timeout; documented.
 - SDK API drift → pin versions; check docs per feature.
 - Labels wrong → UNVERIFIED until Naveed verifies them.
